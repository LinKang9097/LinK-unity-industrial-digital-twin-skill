# 设备告警展示

适用于设备标红、闪烁、报警标签、报警列表、报警弹窗和报警恢复。告警模块是异常视觉覆盖层，不应破坏设备基础状态和原始材质。

## 职责边界

负责：

- 接收内部告警事件或告警状态。
- 对设备进行标红、闪烁、高亮、图标或标签展示。
- 在 UI 中展示报警内容、等级、时间、设备名和处理状态。
- 告警恢复后还原设备视觉状态。

不负责：

- 不建立网络连接。
- 不解析 MQTT topic 或 WebSocket 原始 JSON。
- 不决定设备业务状态是否真的异常。
- 不修改设备动作驱动的核心运行状态。

## 告警模型

建议保留告警 ID，避免重复展示：

```csharp
// 中文注释：告警状态用于视觉覆盖和 UI 展示，不替代设备运行状态。
public sealed class AlarmState
{
    public string AlarmId;
    public string EntityId;
    public string Level;
    public string Message;
    public DateTime StartTime;
    public bool IsRecovered;
}
```

## 视觉表现

常见表现：

- 设备材质标红。
- 外发光或轮廓高亮。
- 闪烁。
- 设备上方报警图标。
- 点击设备显示报警详情。

如果要修改材质，必须记录原始材质或原始颜色，告警解除后恢复。多个告警叠加时，只有所有有效告警都恢复后才取消异常表现。

## 与设备动作的关系

设备动作负责“设备正在做什么”，告警负责“设备异常如何覆盖显示”。告警可以让设备视觉上变红或暂停某些表现，但不应把动作脚本中的运行状态改写成另一个业务状态。

## 与 UI 的关系

告警模块提供告警数据和选中事件；UI 模块负责列表、弹窗、详情面板和关闭逻辑。

## 验证重点

- 告警出现时设备能正确标红。
- 告警恢复后材质能还原。
- 同一告警重复上报不会重复创建 UI 项。
- 多个告警叠加时不会提前恢复正常颜色。
