# 楼层管理

适用于多楼层工业数字孪生场景中的楼层切换、楼层可见性、楼层相机视角、设备/货物/库位随楼层显示隐藏。楼层管理是全局场景上下文模块，不属于相机、库存或设备动作的附属功能。

## 职责边界

负责：

- 维护当前楼层，例如 `CurrentFloorId`。
- 管理楼层元数据，例如楼层名称、中心点、包围盒、默认相机位、默认俯视尺寸。
- 处理楼层切换，并广播 `FloorChanged` 事件。
- 协调场景对象按楼层显示或隐藏。
- 为相机、设备、库存、UI 和告警提供当前楼层上下文。

不负责：

- 不直接实现相机补间、旋转、跟随或漫游算法。
- 不直接驱动 AGV、输送线、提升机等设备动作。
- 不因楼层切换暂停、停止或冻结非当前楼层设备。
- 不直接生成、删除或改变真实库存。
- 不直接解析实时消息或 HTTP 数据。
- 不把 UI 按钮逻辑写进楼层核心管理器。

## 核心模型

楼层数据应尽量配置化，避免把楼层坐标、相机位置和可见性规则散落在脚本中。

```csharp
// 中文注释：楼层配置描述楼层的空间范围和默认视角，不保存业务库存或设备状态。
public sealed class FloorConfig
{
    public string FloorId;
    public string DisplayName;
    public Vector3 Center;
    public Bounds Bounds;
    public Vector3 DefaultCameraPosition;
    public Vector3 DefaultCameraEulerAngles;
    public float OrthographicSize;
}
```

楼层对象绑定建议使用稳定字段：

```csharp
// 中文注释：场景对象通过楼层 ID 参与显示隐藏，由楼层管理器统一协调。
public sealed class FloorBinding : MonoBehaviour
{
    public string FloorId;
    public bool VisibleOnAllFloors;
}
```

## 楼层切换流程

推荐流程：

```text
UI 或业务事件请求切换楼层
-> FloorManager 校验 floorId
-> 更新 CurrentFloorId
-> 广播 FloorChanged
-> 相机模块切换到楼层默认视角
-> 设备、库存、货物、库位根据楼层显示隐藏
-> UI 更新当前楼层状态
```

楼层切换本身应是轻量状态变化，只改变当前楼层上下文、可见性和相机观察意图，不改变设备运行状态。不要在切换时重新请求所有业务数据。需要刷新数据时，由对应模块自行决定是否通过 HTTP 或实时快照补齐。

## 可见性规则

默认规则：

- 当前楼层对象显示。
- 非当前楼层对象隐藏。
- 非当前楼层设备隐藏后仍然正常接收状态、更新运行数据、推进任务和维护本地运行状态。
- 配置为 `VisibleOnAllFloors` 的对象始终显示，例如厂房外壳、楼梯、电梯井、全局指示牌。
- 跨楼层设备可以按项目配置特殊处理，例如提升机井道全楼层显示，但轿厢只在当前或相关楼层显示。

AGV、货物、库位、托盘、设备模型都应绑定楼层 ID。没有楼层 ID 的对象不要盲目隐藏，优先按项目约定归入全局层或默认楼层。

## 相机联动

楼层切换后，相机应切换到该楼层适合观察的视角：

- 默认使用楼层配置中的相机位置和角度。
- 移动和旋转保持平滑，默认 1 秒。
- 如果当前处于俯视模式，应更新正交尺寸和俯视中心到当前楼层。
- 如果当前处于设备跟随或设备定位，可按项目策略决定是否退出跟随，或切换到目标设备所在楼层。
- 楼层切换只发出相机意图，具体补间和正交/透视切换由相机模块实现。

推荐接口：

```csharp
// 中文注释：楼层管理器只维护当前楼层和广播事件，不直接写相机运动细节。
public interface IFloorManager
{
    string CurrentFloorId { get; }
    void SwitchFloor(string floorId);
    FloorConfig GetCurrentFloor();
}
```

相机模块可以提供对应入口：

```csharp
// 中文注释：相机根据楼层配置调整视角，过渡时间默认使用相机配置。
cameraController.FocusFloor(floorConfig);
```

## 设备与库存联动

设备和库存模块响应楼层变化，而不是由楼层管理器直接改它们的内部状态。

设备模块：

- 根据设备绑定的 `floorId` 控制模型显示隐藏。
- 非当前楼层设备被隐藏时，设备驱动和状态缓存仍应继续运行；隐藏只影响渲染表现，不影响状态更新、任务进度、位置计算或动画状态机。
- 切回楼层时，设备应展示最新状态，而不是从离开楼层时的旧状态继续。
- AGV、RGV、堆垛机等移动设备需要随当前位置或后端楼层字段更新楼层绑定。
- 跨楼层动作中的设备可以临时显示在相关楼层，具体规则由设备模块处理。

库存模块：

- 根据货物、库位、托盘的 `floorId` 控制显示隐藏。
- 切换楼层不改变库存真相，只改变可见性。
- 取放货导致货物楼层变化时，以后端库存事件或快照为准。

## UI 与告警联动

UI 负责展示楼层入口和当前楼层，不直接隐藏场景对象：

```csharp
// 中文注释：UI 只表达切换意图，楼层管理器负责广播楼层变化。
floorManager.SwitchFloor("F2");
```

告警模块可以显示报警所在楼层。点击非当前楼层的告警时，推荐流程是：

```text
点击告警
-> 请求切换到告警设备所在楼层
-> 相机定位到告警设备
-> 打开告警详情
```

告警模块不应自己隐藏或显示楼层对象。

## 验证重点

- 切换楼层后相机能平滑切换到该楼层默认视角。
- 当前楼层的 AGV、货物、库位和设备可见，其他楼层按规则隐藏。
- 俯视模式下切换楼层会更新正交尺寸和中心点。
- 点击非当前楼层告警时能切换楼层并定位目标设备。
- 楼层切换不会改变库存真实状态或设备运行状态。
- 非当前楼层设备隐藏后仍会继续更新运行状态，切回楼层时能显示最新状态。
- 没有楼层绑定的对象不会被错误隐藏。
