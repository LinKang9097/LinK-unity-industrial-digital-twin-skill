# 模块边界与重叠处理

当实时接入、HTTP、设备动作、告警、UI、库存、楼层和相机之间职责不清时，优先按本文件拆分。目标是让每个模块只承担一种变化原因。

## 总体规则

```text
实时接入层只产生事件，不直接驱动场景。
Unity 不管理 PLC 通信、读写区、握手、清除指令或任务下发流程；这些由后端处理，协议文档只作为字段含义参考。
HTTP 层只服务查询型 UI 数据，不承担实时同步。
设备动作只负责设备怎么动，不负责库存真相。
设备取放货动作优先由当前设备脚本或当前设备子类处理；总管理器不集中编排所有设备的取放货细节。
起始/终点站台负责标注货物进入或离开场景的位置；实际货物生成和删除由库存模块执行。
普通设备管理器只负责场景内非 AGV 设备的注册、查找和通用设备操作，不实现具体设备动作。
AGV 管理器只负责 AGV 的动态生成、查找、车型 prefab 选择、AGV 地图坐标映射和 AGV 生命周期。
库存模块只负责货物、货架、库位状态、货物模型选择、库存生成、货架筛选和在途货物归属，不负责设备运动。
告警模块是视觉覆盖层，不改写设备基础状态。
UI 只做界面生命周期和显示绑定，不解析底层协议。
楼层只负责当前楼层上下文和可见性协调，不实现相机运动、设备动作或库存增减；非当前楼层设备隐藏时仍继续运行。
相机只负责视角行为，由 UI 或场景事件触发。
```

## 常见重叠区

### 实时消息和设备动作

实时消息负责把外部状态转换为内部事件；设备动作负责消费事件并表现动作。

不要这样做：

```text
MQTT 回调 -> 直接移动 AGV Transform
```

推荐这样做：

```text
MQTT 回调 -> 内部 AgvPositionUpdated 事件 -> 主线程状态更新 -> AgvDriver 插值移动
```

普通设备消息进入普通设备管理器后，应按 `deviceId` 找到对应 `BaseDevice` 子类，再由子类处理自己的运行逻辑。AGV 消息进入 AGV 管理器后，应按 `agvId` 查找或动态生成 `BaseAgv` 子类，再由 AGV 子类处理车型表现。管理器负责“找到谁”，子类负责“怎么动”。

协议字段如 `DeviceNo`、`Alarm`、`Load`、`State`、`Source`、`Target`、`TaskNo`、`ContainerNumber` 只表示 Unity 已收到的设备状态输入。不要把 PLC 读写、WCS 下发、任务确认、指令清除等后端流程写进 Unity 模块。

### 普通设备和 AGV

非 AGV 设备通常已在场景中摆好，由普通设备管理器启动时从指定父物体递归读取并注册。AGV 通常不预先摆放，而是根据实时或历史数据动态生成。

不要把普通设备和 AGV 统一进一个万能基类。它们的生命周期不同：

- 普通设备：场景预置、启动注册、通过 `deviceId` 查找、子类实现数据处理。
- AGV：数据驱动创建、按 `agvId` 查找、按车型选择 prefab、按 `mapId` 使用对应地图原点换算坐标。

两者可以共用载货点接口、告警接口、ID UI 接口等小契约，但不要强行共用创建流程、地图坐标流程或任务流转规则。

### 实时消息和 UI

实时消息可以更新本地状态；UI 订阅状态变化或 ViewModel 更新。

不要让 UI 直接订阅底层 topic 或解析原始 JSON。这样会导致换协议时 UI 大面积改动。

### HTTP 和实时消息

实时消息回答“现在发生了什么”，HTTP 回答“这个对象的详细信息是什么”。

例如：

```text
收到 alarm.raised -> 告警摘要立即出现
用户点击告警 -> HTTP 查询完整告警详情
```

### 设备动作和库存

设备动作表现搬运过程，库存表现货物事实。

如果为了视觉效果需要把货物临时挂到设备上，应明确这是视觉挂载。最终库存位置仍以后端库存事件或快照为准。

在途货物的对象归属由库存模块管理，承载设备的移动由设备动作模块管理。设备可以提供货物挂载点，但不直接创建、删除或决定货物真实归属。

设备动作模块可以根据任务号或托盘条码协调普通设备上的货物流转，AGV 可走独立状态或坐标协议。未扫码临时任务号必须作为特殊链路处理，不进入正常任务流转规则。

所有设备都应暴露载货点。设备模块负责载货点位置和跟随关系，库存模块负责把货物挂到载货点或从载货点解绑。

设备取放货的机械表现，例如 AGV 顶升、堆垛机货叉伸缩、桁架夹具抓取、提升机托盘进入离开，应放在当前设备脚本或当前设备子类中。需要跨设备协调时，可以通过事件表达交接关系，但不要新增一个中心脚本直接控制所有设备的取放货动作和流转细节。

起始站台和终点站台是运行时货物增删的唯一入口。设备动作模块可以在对应站台检测到上料、下料、入场或离场时发出生成/删除意图，但库存模块负责真正创建、销毁、回收和维护索引。初始化快照是例外：程序启动后，后端推送所有字段上一条数据时，库存模块可以根据设备载货状态直接重建已有货物。

### 告警和设备动作

告警是设备表现的覆盖层。设备可以继续保持运行、停止或离线表现，但红色、闪烁、报警图标由告警层控制。

告警恢复时，告警层应恢复自己改过的材质、颜色或特效，不重置设备动作模块的状态机。

### UI 和相机

UI 触发相机意图，相机模块执行移动。

推荐调用：

```csharp
// 中文注释：UI 不关心相机轨迹，只表达用户想定位哪个对象。
cameraController.Focus(entityId);
```

不推荐在 UI 按钮回调里直接写相机补间、旋转和跟随逻辑。

### 楼层和相机

楼层模块决定当前楼层，相机模块决定视角如何移动。切换楼层时，楼层模块广播楼层变化；相机模块根据楼层配置平滑切换到默认视角、更新旋转中心或调整俯视正交尺寸。

不要这样做：

```text
FloorManager -> 直接设置 Camera Transform 的每个细节
```

推荐这样做：

```text
FloorManager.SwitchFloor(floorId) -> FloorChanged -> CameraController.FocusFloor(floorConfig)
```

### 楼层和设备/库存

楼层模块负责“当前看哪一层”，设备和库存模块负责“自己的对象如何响应楼层变化”。隐藏非当前楼层设备只是渲染可见性变化，不代表设备暂停、停止或冻结。

推荐：

```text
FloorChanged -> DeviceVisibilityController 按 floorId 显示隐藏设备
FloorChanged -> InventoryVisibilityController 按 floorId 显示隐藏货物和库位
```

楼层切换不代表设备停止、不代表库存移动，也不代表要重新计算业务状态。非当前楼层设备仍应继续接收实时消息、更新状态缓存、推进动画/位置计算；切回楼层时显示最新状态。

AGV 地图切换也不等同于楼层切换。AGV 地图上下文用于选择坐标原点和轴向映射；楼层上下文用于决定当前可见范围和相机视角。需要同时处理时，先用 AGV 的 `mapId` 完成坐标换算，再由楼层或地图可见性控制决定是否显示。

### 楼层和 UI/告警

UI 可以调用楼层切换接口，但不直接隐藏场景对象。告警可以携带楼层信息；点击非当前楼层告警时，可以先切换楼层，再请求相机定位告警设备。

### 库存和 UI 货架筛选

UI 可以触发“只看某个货架”，但不直接隐藏货架或货物。库存模块根据 `rackId` 处理货架、库位和货物的显示隐藏，并与当前楼层筛选叠加。

```text
点击 1 货架 -> UI 调用 ShowOnlyRack("1") -> 库存模块只显示 1 货架及其货物
```

货架筛选不改变库存真实状态，也不暂停在途货物或设备运行。

### 初始化快照和实时增删

初始化快照回答“程序启动时现场已经有什么”。实时增删回答“程序运行后哪些货物从场景入口进入、从场景出口离开”。

推荐：

```text
初始化快照 -> 库存模块按上一条数据重建货物
实时起始站台事件 -> 库存模块生成货物
实时终点站台事件 -> 库存模块删除货物
```

不要让每个载货点都拥有运行时生成/删除权限。输送线中间段、AGV、RGV、提升机、堆垛机、桁架等对象即使检测到有货，也只表示已有货物正在该位置，不表示它们能凭空创建或销毁货物。

## 决策口诀

当不确定代码应该放在哪个模块时，问这几个问题：

- 这是外部数据进入 Unity 吗？放接入层。
- 这是打开面板时查询详情吗？放 HTTP 服务和 UI 层之间。
- 这是设备如何运动吗？放设备驱动。
- 这是当前设备的取货、放货、载货点切换或机械动作吗？放当前设备脚本或当前设备子类。
- 这是运行时货物从场景入口生成或从出口删除吗？由起始/终点站台发出意图，库存模块执行。
- 这是程序启动时根据上一条数据还原已有货物吗？放库存初始化流程。
- 这是非 AGV 场景设备的注册和查找吗？放普通设备管理器。
- 这是 AGV 动态生成、车型选择或地图原点换算吗？放 AGV 管理器。
- 这是异常如何显示吗？放告警模块。
- 这是货物或库位是否存在吗？放库存模块。
- 这是平库/立库、货架绑定、货架筛选吗？放库存模块。
- 这是界面如何开关和显示吗？放 UI 模块。
- 这是当前显示哪一层、对象是否随楼层显示隐藏吗？放楼层模块。
- 这是视角如何移动吗？放相机模块。
